# 分析与改进设计：从「限墨配方」到「可诊断配方」

> 本文记录一次对标研究：本技能（taxue-halftone，下称「本系统」）与两类参考流在「分析」与「出 Prompt 设计」上的优劣对比，以及据此提出的改进与消融结论。
> 参考流 A：以真实照片为输入、多图协同（原图 + 主导参考 + 垫图）整体重绘的工程化流。
> 参考流 B：无源图主题转译、机器可读设计系统 + 配方清单 + evals 的当代限墨流。
> 为保持原创边界，本文不引用任何外部技能名称，只讨论机制。

## 一、问题重定义

原始问题：「借鉴 A 的照片分析、参考选择、字形设计、垫图管线」。

重新定义为：**在不引入重依赖（OpenCV / 垫图 / 长脚本管线）的前提下，把「输入 → 六轴配方」这一步从『凭感觉』变成『可诊断、可追溯、可校验』；并把「高质量参考的机制迁移」与「原创防火墙」合并成同一个机制。**

为什么这样重定义：
- 本系统现有优势层是「机制物理 + 可校验数据层 + 反模式雷达 + 中文排版规则」，这是 A、B 都没有的深度；无法证明价值的重管线移植只会增加维护成本（A 的脚本管线约 5000 行、附带 OpenCV 依赖、专用于建筑照片域）。
- 本系统最大缺口不在「出图」而在「接案到配方」的中间地带：`scenes.md` 是按主题路由的粗表，缺少「照片/图源特征 → 轴取值」的确定性映射，也没有「分析结论」的产物结构。
- 因此改进目标是提高**决策可追溯性**与**输入适应性**，而不是复制 A 的表单数量。

## 二、MECE 分层对比

把三家拆到五个正交层比较（先分后比，避免「这个比那个好」的笼统结论）：

| 层 | 覆盖问题 | 流 A | 流 B | 本系统 |
|---|---|---|---|---|
| 1 分析层 | 输入解析成什么 | 量化预检（构图轴/主色/占幅/评分）+ 事实分级 + 四域命题 | 四要素读取（主体/意图/词/图角色 + 表示法） | §1 配方字段（含主体结构链、意图、来源策略），无读取步骤 |
| 2 决策层 | 输入如何变成配方 | Token 检索 + 四步适配 + 常见照片方向表 | Defaults 表 + 通用词别名 + 同输入同配方 | scenes.md 场景路由 + styles 指纹 + 未指定默认 |
| 3 出图层 | 提示词怎么组织 | 三图编译（原图/参考/垫图）+ 单方向提示词 | 五段编译 + 锁定句 | 五段编译 + 锁定句（与 B 同构，判断为同源思路） |
| 4 质量层 | 怎么防翻车 | 8 硬门 + 五项读回 + 不自动重生成 | eval schema + CI + 目录交叉校验 | 3 套校验 + 10 evals + 18 命名反模式雷达 + blocker 判语 |
| 5 成本层 | 多少运行成本 | 重（~5k 行脚本、OpenCV/PIL、每 run 多产物） | 轻（纯文本 + JSON + CI） | 轻（纯文本 + JSON + stdlib 校验脚本） |

### 量化对比

| 维度 | 流 A | 流 B | 本系统 |
|---|---|---|---|
| 风格/机制数量 | 1 套（单域：建筑照片） | 1 类机制（半调）+ 7 类字声部 | 7 种机制 × 10 风格指纹 |
| 可校验数据层 | 无断言体系 | colors/typography/compositions/rhythm 目录 + evals schema + CI 交叉校验 | roles/bools/mechanisms/behaviors/volume/subject/platform 目录 + 3 套校验 + 10 evals |
| 命名反模式 | 无（有隐性禁令） | 有隐性「禁止复刻参考字句」条款 | 18 个命名模式（含签名 + 正确替代），可扫描 |
| 中文处理 | 字形谱系 6 家族 + 逐字光学补偿（重） | 以英文为主，中文简略 | CJK 网距/type-off 默认/type-in 印刷事件规则（已深） |
| 输入照片 | 支持（核心场景） | 支持（2-4 锚点保留身份） | 支持（来源策略三选一，但无读取步骤） |
| 参考迁移 | 核心机制（主导参考 + 掏空判定） | 禁止复刻（防火墙） | 禁止复刻（reference-reprint 反模式） |
| 配方稳定性 | 未声明 | 显式保证（同输入同配方） | 部分（种子 = hash 主体/文本/palette/layout） |

结论（本系统）：
1. **质量层与决策层已超 A / 持平 B**，不需要移植 A 的门控数量。
2. **分析层是唯一短板**：A 有「读数」产物，本系统只有「该填什么」的字段。这是拉差距的地方。
3. **参考迁移能力本系统有意缺席**（原创立场），但「如何从可选参考中只迁移机制」可以以可选开关加入，且与现有 reference-reprint 反模式天然兼容（迁移的是机制，复制内容仍被禁止）。

## 三、优秀思路的提炼（哪些机制值得学）

按「能否证明价值 / 能否轻量实现」二维筛选，得出 5 个候选组件：

| 候选 | 来源思路 | 原始实现成本 | 本系统轻量版 | 证明价值的方法 |
|---|---|---|---|---|
| C1 输入诊断卡 | 照片预检（量化打分） | OpenCV 管线 357 行 | 5 项观察式诊断（构图轴/主体占幅/负空间/主导色/截断或歪斜），产物进配方 | 对照：诊断卡取值与六轴行为轴是否一致 |
| C2 特征→轴映射表 | 常见照片方向表 | 1 张表 | 照片特征 → behavior/mechanism/volume/起点色 的确定性映射（补 scenes 盲区） | 对照：有映射时配方依据可追溯 |
| C3 四域命题 | 命题先于参考、一个主问题一个修复 | 表单 + 门禁用 | 一页：主体域/背景域/互动域/排版动作 + 一个主问题 + 唯一修复动作 | 对照：是否消除双孤岛 / 无主问题的模糊构图 |
| C4 主导参考可选迁移 | 四步适配 + 掏空判定 | token 库 + 参考编码矩阵 | 仅用户提供参考时：几何/拓扑/机制/身份边界四步 + 掏空判定 + 迁移 2-4 个可见机制 | 对照：参考迁移是否改变输出且不触发复刻反模式 |
| C5 中文展示字形速查 | 字形谱系 + 逐字光学补偿 | glyph-brief 管线（重） | 6 谱系 × 5 可见特征一行选择表；不引入逐字简报 | 对照：type-in 时是否给出可指认字形目标 |

不学（证明不了必要性 / 与本系统冲突）：
- Token 检索库（835 行）：本系统的「取指纹」替代——风格就是指纹组合，检索重复度问题已由 scenes.md + 反模式防「高使用率组合」覆盖；引入 Token 库会推翻「风格=指纹」的原设计。
- 垫图管线（887 行 typeset + 584 行 prepare_generation）：需要真实字体、蒙版、依赖链；本系统 type-off 后期叠字默认 + type-in 印刷事件规则已覆盖文字准确性路径。
- 8 硬门：本系统 blocker 卡 + 反模式雷达已覆盖等价的翻车项。
- 事实分级（VERIFIED/OBSERVED/...）：本系统场景是「任意主题/图」，不是史实域，无此需求。

## 四、改进目标函数

```
max  配方可追溯性（每轴取值有 1 条来源证据）
max  输入适应性（照片 / 主题 / 参考 三类输入都有确定路径）
max  输出稳定性（同输入同配方；新增组件不得破坏现有 10 evals + 3 校验）
min  新增成本（≤1 个新文件 + SKILL.md 净增 ≤120 行；零新增依赖）
min  复刻风险（任何新增机制不得扩大「复制参考实体」的可能性）
```

## 五、消融实验设计

### 实验协议

- 输入集：I1 有照片（竖拍街景、有汉字店招、轻微歪斜）；I2 纯主题无源（「深秋的银杏」）；I3 提供参考图（一张双色孔版海报，供 C4 触发）。
- 配置：ALL（全开）/ NONE（基线，等价旧版流程）/ 各候选单独摘除（ALL-C1 ~ ALL-C5），共 7 配置。
- 评测（确定性部分）：配方完整性（18 字段）、轴取值合法性（对 design-system 目录校验）、反模式扫描（18 命名模式信号词）、成本（新增阅读行数）。
- 评测（判断部分）：诊断→取值一致性（如 behavior=horizon 时证据是水平轴）、主问题是否落到 prompt 的修复句、参考迁移是否因掏空判定而被否决。
- 判定：某候选在 3 个输入上均无可观测输出差异 → 删（无法证明必要性）；有差异但引入复刻风险/增加不确定性 → 删；有差异且正向 → 保留。

### 预期

- C1+C2 预期联动（诊断卡提供证据，映射表提供取值），单独摘除 C2 时应观察到「行为轴取值靠猜」。
- C3 预期在 I1 上消除「双孤岛/无主问题」。
- C4 预期只在 I3 改变输出；对 I1/I2 应无影响（默认不启用参考）。
- C5 预期在 I2（中文标题 type-in）上生效。

## 六、结论（消融后填写）

### 实验执行

21 个回放任务（3 输入 × 7 配置，按版本化 SKILL 变体执行，输出配方 + 五段 prompt），由确定性检查器评分（配方字段完整性、六轴取值合法性、反模式扫描、诊断→取值一致性）。第一轮评分暴露两处工具误报（反模式信号命中「禁止句」、behavior 连字符与 JSON 下划线不一致），修正检查器后指标干净：全部配置轴取值 100% 合法、配方字段 19–20/20。

### 逐项消融判定

| 组件 | 证据 | 判定 |
|---|---|---|
| C1 诊断卡（独立块） | 剥离后（C2+C3 仍在）诊断与命题照常产出，只差「结构化五行」格式；配方模板字段本身也引导诊断 | **删除独立块**，五行模板并入 C2 的「诊断与映射」节，格式收益保留、重复结构消除 |
| C2 特征→轴映射 | 有映射时每轴带来源注记（`behavior ← 诊断 axis=…`）；剥离组出现角度自相矛盾（15° apart 却又写 ≥30°）之类松懈 | **保留**（与 C1 合并后） |
| C3 四域命题 | 图源输出中「四域非原样保留/普通渐变/居中」判语约束了设计判断；但无源输入时被用作「预防性措施」填空（把反模式预防写成修复动作） | **保留**；补一句严格化：defect=none 或无源时只写「无主问题」，不得用预防充当修复 |
| C4 主导参考迁移（独立节） | 剥离后三份输出仍自发完成参考迁移（借技法、拒实体），质量接近；独立节的净增只有「掏空判定」这一检查点 | **大幅精简**：14 行独立节 → §7 一行（迁移 2–4 个可见机制 + 掏空判定），保留检查点、去掉重复结构 |
| C5 中文展示字形速查 | 剥离组字形描述退化为字体名（blackface/Gothic），保留组写满 4–6 个可见特征（方/等高/1:2.5/楔脚/字腔/基线） | **保留** |

### 顺带修复（消融中发现，非新增）

- 配方模板 `behavior: vertical-extend` 与 `design-system/behaviors.json` 的 `vertical_extend` 不一致，导致校验器判非法；已统一为 `vertical_extend`（可校验性）。
- checker：反模式扫描只计前四段（第 5 段硬禁止句是正确用法），行为轴做 `-_` 归一化。

### 净变化

- SKILL.md：154 行 → 224 行；相对初始改动（加五个组件的 237 行版本）**削减 13 行复杂性**，保留 C2/C3/C5 三个已验证组件 + C4 检查点一行。
- 新增两个实验脚本（ablate.py、checker.py），零第三方依赖。
- 回归：design-system / styles / evals 三套校验全部通过；10 个既有 eval 断言无回退。

## 附：可验证的观察

- 图源诊断的「轴→behavior」与「占幅→volume」一致性打分在 ALL 组为 0 冲突（排除扫描器误报后）；NONE 组凭常识也能选中正确取值，但无来源注记，回归时无法机器复检。
- 三种输入（照片/主题/参考）在 ALL 配置下都走完「诊断 → 映射 → 命题 → 配方 → 五段」链，无缺环。

### C6 补充消融（参考创作模式，2026-09-03 追加）

用户提出「利用本系统经典风格自带样张做参考创作」后新增候选 C6，4 个回放验证（R1 本系统成品样张 / R2 外部作品 × 有 C6 / 无 C6）：

| 回放 | 有 C6 | 无 C6（仅 §7 一行） |
|---|---|---|
| R1 本系统成品（editorial 指纹） | 显式 style_lockup → 锁定 styles/editorial.json 六轴，明示不复刻实体 | 同样锁定 editorial（凭 examples/README.md 映射 + 常识），并补掏空判定 |
| R2 外部作品（DOG DAYS 海报） | 显式比对后否决风格锁定（最接近 dot_dissolve 但纸墨角色不符），转机制迁移 4 项 | 未做指纹比对，随手以 editorial 为基底，迁移 3 项 |

判定：C6 的输出质量增量有限（R1 两组几乎一致；R2 差异只在「显式比对 + 否决」的决策过程），其必要性与 C4 当年相似。按「删除无法证明必要性的复杂性」，把 §1.6 从 16 行压缩到 5 行，只保留判据（同指纹 → 锁 style_id）与否决（不符 → §7 机制迁移）+ 验收（可指认动作 + 宁少勿多）。行数净增 5 行 vs 现状 1 行，换的是「参考本系统成品 → 直接复用整套风格指纹」这一用户可感知能力；`examples/README.md` 的样张→风格映射表成为该能力的钥匙。
